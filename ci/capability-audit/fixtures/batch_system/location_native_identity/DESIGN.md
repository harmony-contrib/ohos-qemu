# Actual native UIExtension identity carrier — source design

This is diagnostic source work only. No actual source/out, tests, compiler, SDK, VM/HDC, signing, Docker or Git operation was executed by the location agent. All frozen15 runtime sources remain unchanged. Existing observations remain E facts, not F proof.

Two existing native dumps need a shared actual session value. The actual UINode DumpTree puts native AccessibilityId and then invokes FrameNode::DumpInfo→UIExtensionPattern::DumpInfo in the same node scope. UITest copies the platform element AccessibilityId; it is distinct from FrameNodeId. Therefore the original raw native AccessibilityId, actual hostWindowId, same UI owner/process generation and full reviewed pane scope can identify the native component without ordinary.id or encoded-bit guesses.

ArkUI additive existing-Dump record: version=1, rendererPid/rendererUid from real getpid/getuid, actual host FrameNodeId, actual host AccessibilityId, sessionWrapper.GetSessionId (the actual session.GetPersistentId getter), existing focusWindowId and realHostWindowId. String and JSON overloads report the same raw integer identities before any remote dump forwarding. Export26 proves OHOS UIContentImpl DumpInfo posts the existing UI task, but a direct accessibility dump entry also exists. The new identity therefore samples the mutable wrapper only after the actual existing executor reports WillRunOnCurrentThread(UI); off-UI calls omit only the new line, retaining the old dump. Missing host/session or zero identities cannot become successful runtime mapping. This creates no observer, owner, session, API, socket, JS method, permission or UI input.

AMS additive existing-Dump record: version=1, serverPid/serverUid from real getpid/getuid, actual AbilityRecordId plus record SessionInfo persistentId, hostWindowId, realHostWindowId and usage. The actual ExtensionSessionManager copies the same actual session.GetPersistentId into AMS SessionInfo; no surrogate ordinal or newly minted nonce is used. Export26 proves GetSessionInfo is const, takes the actual sessionLock and returns a strong sptr. The new carrier holds that object and never accesses its mutable sessionToken. Existing bundle/module/ability/foreground/root-host/provider PID sections remain and must all match full new-package HAP/image/signature/BMS+AMS/proc proof. serverPid is the dump emitter, never the extension provider PID.

The raw selected pane/native-node carrier must join the AMS carrier on the real persistentId, exact host window and actual source/record identity. Validate both fresh UI cuts, native window/renderer dump bounds and same host/provider generations. Ambiguous/detached/zero/mismatched/missing/version-unknown/duplicate carrier is a gap and permits no UI input. Native getters yield a sampled relation, not global atomic state; repeat stable reads and source-proven task/lock constraints are mandatory. Geometry, one pane, one provider PID, fixed Want, random nonce, local ordinal or event time cannot create the relation.

Exact whole E pre/post source hashes, authentic raw fixture copies, known final/replay and unknown/partial/mixed-source rejection will accompany both patch components. Shared source helpers and recipes remain root-owned. Root must integrate both components together and verify both complete final states before compiling/packaging. Current new-package behavior gate remains false and 0 IDs close.

`source-proof.json` retains export20–26 manifests, all verified original file hashes, absent lists and actual project heads. The two changed CPP files preserve all existing behavior outside additive include/diagnostic blocks; there is no new permission path. Existing WMS native-token/hdcd and AMS shell/hidumper authorization must actually succeed; UID0 text alone grants nothing. Root must restrict recipe integration to its QEMU graph and compile both actual product TUs with existing CFI/LTO flags, then bind the new image DSOs to targeted actual carrier processes. Source checks and host fixtures are not that proof.

Root future read-only native tree command uses the actual fresh hostWindowId: `hidumper -s WindowManagerService -a '-w <id> -default -lastpage -nouie'`. Existing `-nouie` is explicitly recognized by the actual Pattern and stops only extra remote UIExtension dump forwarding, after the new carrier and old local fields. It prevents remote-renderer local accessibility IDs being mixed into the host tree. No remote node ID bit arithmetic is used. AMS is read through existing `aa dump -a`; exact carrier and complete actual foreground/reciprocal process sections remain required even if a CLI reports exit0.
