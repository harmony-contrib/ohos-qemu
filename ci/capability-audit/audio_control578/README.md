# Audio same-boot CONTROL inputs

These source patches preserve the original Audio collector and original process
Owner. Apply the complete set to a fresh derived source kit before binding its
actual new commit/package/profile identities. The full native source is tracked
in `../fixtures/batch_media/audio_control404/pcm_status_observer.c`.

The pre-guest configuration admits only real compiled tools and image profile;
its holder inventory is null. On the newly packaged QEMU guest, the status tool
finds an existing original CONTROL listener and its playback descriptor. It
queries the borrowed existing descriptor with pidfd_getfd, kcmp and PCM INFO,
records two stable process/credentials/namespace/OFD cuts, closes its duplicates,
and derives the original strict thirteen-field configuration before CONTROL ARM.
It never opens a PCM pathname or changes its parameters.

The fixed fresh-guest dispatch uses the original Owner.run, existing child seam,
held guest, raw BM UDID checks and final finish/quarantine. Previous signing
inputs may be reused only after this fresh guest confirms the actual same UDID.
Native helper source changes require real newly compiled guest-tool receipts;
old tool receipts cannot authorize the new source.

Inventory readiness, CONTROL and kernel samples remain diagnostics. They do not
prove source frame zero, audio onset, public timing, a closed capability ledger,
or the representative package gate. Only actual newly packaged QEMU results can
supply those verdicts. No host test or independent SDK replay is part of this
source delivery.
