# SceneBoard WindowManager QEMU packages (2026-09-19)

The release directory is
`/Volumes/PSSD/qemu/packages/window-manager-2in1-20260917`. It contains six
archives, `SHA256SUMS`, `matrix-manifest.json`, and runtime evidence.

The three 2in1 archives enable SceneBoard and the PC window layout. Their
headless boot configuration publishes both `usual.event.USER_UNLOCKED` and
`usual.event.SCREEN_UNLOCKED` for user 100. OpenHarmony 7.0 AbilityManager
requires both events before it removes the first-boot UI-ability interceptor.
The three phone archives are unchanged hard links to
`device-matrix-child-process-enabled-20260917`; the SceneBoard and unlock-event
changes do not apply to phone.

The arm64 2in1 archive passed the required first-package gate before x86_64
and armv7a were repackaged. The gate record is
`validation/arm64-2in1/first-package-gate.json`. Each 2in1 result was produced
by extracting its final archive into a fresh directory, checking the package
and ELF metadata, cold booting it, and running the WindowManager and Native
child suites through `ci/window-manager/validate-package.sh`.

The final 2in1 evidence directories are:

- `validation/arm64-2in1/user-and-screen-unlock-final`
- `validation/x86_64-2in1/user-and-screen-unlock-final`
- `validation/armv7a-2in1/user-and-screen-unlock-final`

The WindowManager suite covers visible layouts, the active test window, the
API-26 capability matrix, and asynchronous callbacks. The Native child suite
covers 21 cases, including empty input, exact 150 KiB ASCII and Unicode input,
16 file descriptors, limit rejection, and recovery. ARMv7a uses isolated app
launches for the Native child cases to avoid repeated restart timeouts under
TCG.

The renewed SceneBoard HAPs use a development certificate and provisioning
profile. Each 2in1 `device-profile.json` records their source revision, native
ABIs, profile validity, and SHA-256 hashes; the package verifier compares the
installed files in `system.img` with that evidence.
