## Actual data path and oracle

The product's existing `mac80211_hwsim radios=2` creates two phys in the initial netns. The helper moves the idle, unaddressed spare wiphy via actual `NL80211_CMD_SET_WIPHY_NETNS` into a held `unshare(CLONE_NEWNET)` namespace. Both radios retain their creation-time hwsim netgroup in this actual kernel. The initial radio and isolated peer have different network-stack inodes and different MACs. The OS creates its AP interface on its own phy after wlan1 is freed. Namespace, ioctl addresses, kernel routes/ARP and raw radio packets are retained. There is no localhost endpoint, veth/NAT shortcut, or initial-netns DHCP-SA proxy.

For OS STA, stock hostapd runs on the isolated radio; a fixed guest-only DHCP/DNS/HTTP/UDP peer provides 192.0.2.1/24 and actual DORA lease 192.0.2.2. For OS AP, stock wpa_supplicant authenticates the isolated STA and an AF_PACKET DHCP client exchanges actual broadcast DORA with the OS's real DHCP server before configuring the returned address. The client starts without a retained IPv4 address or route. MAC/XID/OFFER/REQUEST/ACK must agree with public linked/station IP state. Each UDP data exchange draws a new random challenge before transmission and requires actual initial TX, isolated RX/TX, initial RX, and independent AF_PACKET frames containing both directions. All initial-netns local addresses and 127/8 are explicitly excluded as peer targets.

The actual `/system/etc/netdetectionurl.conf` exists in both exported source and package. A reversible bind mount supplies fixed nonce primary/fallback HTTP(S) URLs using `wifi.apps579.invalid`, `wifi-fallback.apps579.invalid` and `login.apps579.invalid`, resolved by actual isolated DNS over the WiFi network. Before browser authorization, real HTTP detectors receive 302 to a nonce login page. Real OS notification click opens PortalLogin, whose source binds to the supplied WiFi NetId. Back/cancel is recorded; the real nonce link authorizes the peer, which then returns dual HTTP204. The same actual WiFi NetHandle must gain native capability16 VALIDATED. There is deliberately no TLS443 fixture here: original HTTPS connection failures are retained, and no claim of HTTPS or CA acceptance is made. This follows the actual NetMonitor dual-HTTP-success branch, not an assigned connectivity state. Original config SHA must be restored.

After ordinary-caller death/reentry, its persisted private network ID is removed through public WiFi APIs before reconnect. OS AP then proves real independent peer join, DHCP, nonce data, station enumeration and departure/native callbacks. Empty AP is observed for at least default600000 ms (plus10000 ms grace) measured by actual caller `active_ms`, bounded by host660 s. If the OS actually closes it, only the genuine hotspot-disabled notification is clicked; actual reenable, independent peer rejoin/new DORA and data must follow. If it remains active, that is a retained unsupported-boundary observation, not a successful idle implementation. Thermal snapshots preserve actual zones/temperatures where present; this fixture never injects a fake thermal event.
