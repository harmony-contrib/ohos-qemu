# 本批镜像验收约束（578）

本批只以新构建 QEMU 镜像中的实际行为作为能力验收依据。按用户最新指示，不再安排宿主回归或独立 SDK 验证轮次；此前记录保留为历史排错证据，不能关闭能力缺口。源文件身份和构建输入快照用于确定被测版本，被测应用编译与签名用于准备镜像内调用者，均不计为验收通过。

五组候选集中到唯一开发分支，root 统一接线并串行持有构建、签名、HDC、QEMU 资源。当前已接入定位实际 consent/轨迹/图标/围栏原始记录、Graphics3D 非空模型与实际 QMP 六帧、AVScreenCapture/AVTranscoder 实际媒体输出和取消/死亡/通知停止路径、三应用分享与 MMS 附件链、2in1 USB 查询/描述符/授权/插拔链。这些是待测实现，尚无本批镜像运行通过结论。

[固定 OpenHarmony/SIG 提供者边界](provider-support578/REPORT.md)限定默认纯 QEMU 产品缺完整正向 IMS/RTT 和蓝牙控制器/peer 提供者。公共 API、无设备错误、权限、注销、失败回滚仍须镜像实测；现有九项精确 unsupported 不变，没有因此排除额外整个历史 ID。

全部已知产品修复合批后，先完成 ARM64 phone 一份新包的完整启动、全量能力、边界、回归与资源清理，记录包路径、SHA256、环境、命令和原始结果。本轮所有实际失败收齐后统一修复并重测代表包；首件行为门通过后才构建其余五份架构/设备产物。

准备578-01于实际固定源码处拒绝两份陈旧 MMS 基线后自然结束（exit1），容器、launcher、lease 已清理，没有产包。父方依据该构建卷的原始 Git 对象重组有限 MMS 改动，保留固定版本原有业务。默认 SystemUI 安装预置 HAP 的路径也已纳入修复：本批从源码编译 phone 七个或 2in1 八个真实模块，经原 OS 签名装包；保留独立 ScreenLock 原字节。装包步骤逐一比对镜像 HAP 与本轮真实编译输出，实际 BMS 共存、UI 与全部原始行为仍须新镜像验收。所有已知修复将合并后再开始代表构建。
