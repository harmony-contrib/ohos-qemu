QEMU virtual modem TUN endpoint

The normal netsysnative service creates a single nonpersistent `usb0` using
the existing `/dev/tun` permission and capability. The original root developer
shell modem peer receives the descriptor over a fixed abstract sequenced
packet socket. Kernel credentials/context, current boot and finite nonce are
checked. There is no public HAP interface, persistent TUN, new service/process,
capability exception, route mutation or VPN session-channel reuse.

The normal GN translation unit retains the library CFI/link settings. All four
source files and the fixed real project HEAD are checked together. Preparation
rewinds this exact vector before predecessor hooks and reapplies it afterward;
unknown or partial edits fail without weakening predecessor source guards.

Newly packaged QEMU behavior, full source/object/link/image identity, two-role
real CellularNetHandle packet traffic and original peer cleanup remain required.
Source generation alone does not establish acceptance.
