# Actual resampler frame accounting

Source-only component. Apply all four sources as one exact vector, after the existing audio components, then require the final vector before building/packaging. The C filter algorithm and the base Resampler vtable remain exact read-only prerequisites. The independent client/server/Ring component has no managed paths in common with this component.

`apply.sh --source-root /absolute/openharmony` accepts only the complete before or complete final vector. Repeated application is idempotent. `--preflight` checks without writing; `--require-patched` requires all four final sources and never writes. Missing sources, aliases, mixed vectors and foreign bytes fail closed. The parent owns the source lease. A write interruption can leave a partial vector; it is rejected on retry and requires the parent to restore the complete before vector. This is not a four-file filesystem transaction.

The concrete ProResampler API returns consumed, produced, leading-padding and output frame counts without changing the public base vtable. Padding keeps the old leading-zero/output-length policy and is explicitly not source. The converter removes only the actual consumed prefix and retains the tail. It checks processed capacity before advancing the filter. Append, post-conversion, copy, compaction and invalid/zero-progress failures stop the epoch and publish invalid output. Only explicit queue clearing plus successful filter reset, or a new instance, clears the failure. A failed update is never accepted as recovery.

The actual upstream port consumes a block and has no peek or fixed-size contract. Cached work is drained before another pull. A legal variable block is held completely. Its actual frame count must be at most the wrapper's existing 3,840,000-frame bound, its bytes must fit its actual PCM storage, and the queue is bounded by that maximum block plus one input threshold. Aliases into the accumulation queue are rejected before any growth. Storage grows only when a newly observed legal block needs it; this can allocate on the audio thread, so real-time latency and memory still require the new image. If allocation unwinds the epoch remains latched; a no-exception allocation abort is a process failure, not accepted output. The component does not claim failure-path losslessness.

Host checks compile the actual complete wrapper and converter translation units with the unchanged scalar C algorithm under ASan/UBSan. Framework, PCM allocation, channel conversion and logging are explicit dependency models. Original C counts, float output, leading padding, finite failures, variable chunks and queue conservation are checked. These checks do not establish target ABI, GN success, route latency, hardware playback, source-frame zero, or onset. Future source HEAD, source kit and package remain null until the parent creates the actual next build.
