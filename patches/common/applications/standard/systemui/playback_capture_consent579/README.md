# SystemUI playback-capture consent source preparation

This component prepares the complete SystemUI source vector at upstream project HEAD `d0f84037f1975dd9bf13ccbd279bd2d9b56e8a01`. It does not claim successful compilation or runtime behavior. The recorded build failure was the default_dialog CompileArkTS task in representative build579-01. The existing seven phone and eight PC modules, source-provider graph, SDK configuration, signing and permission preparation remain unchanged.

The repaired source declares the three consent constructor fields explicitly and assigns them before the original live-stream check, initializes LocalStorage through typed setOrCreate calls, and uses an explicit EntryOptions with useSharedStorage for the page-level storage supplied by UIExtensionContentSession.loadContent. These retain the per-session consent ID and bundle. No static LocalStorage instance is shared between requests.

The four default_dialog imports of another module's private Log.ts become imports of ../common/Log. The new module-local Log.ts is the complete unchanged, licensed stateless logger from this exact SystemUI HEAD (SHA256 5a6ad08fe269488a91b334656db18d9831b719e775dd017939a22572a67f17a1). The original common logger must still match this hash. Neither the common HAR's exports nor the module's dependency graph is widened.

apply.sh retains the original command-line interface. apply_runtime.py accepts only three complete states: original before12, the previous exact complete legacy8 result plus its four original/absent members, or repaired final12. The project HEAD and all12 whole-file hashes are checked before selecting a transition; any unknown or mixed vector is rejected without publication. legacy_source_states.json and 0000-legacy-product-source.patch preserve the old component bytes for rewind. The immutable old manifest SHA is checked by the new wrapper.

Forward apply uses 0001-product-source.patch from original before12, or 0002-upgrade-legacy-arkts.patch from the actual legacy result. --rewind reverses the matching complete patch to original before12. --require-final accepts only repaired final12. Final apply and original rewind are no-ops. The original canonical component lock path is retained, as are exact patch --binary/--batch/--fuzz=0 staging, full staged inventory, project HEAD checks, source inode/owner/mode checks, owned publication and owned rollback. Publication is transactional with rollback on Python exceptions; it does not claim indivisible multi-file publication or crash recovery. An interrupted or externally mixed vector is refused.

Four unchanged legacy members (module.json5, both string resources, main_pages.json) remain inside the full12 migration guard and are skipped during publication, retaining inode/mtime. New or changed source replacements retain the existing helper's mode/owner handling. Rollback restores the original bytes/mode/owner; changed files need not retain their original inode or mtime. Unknown concurrent content is preserved and reported rather than overwritten.

All native admission, actual stream/UID/source/PREPARED checks, bundle lookup, duplicate-stream guard, default rejection, page IDs, consent result API, 250ms revalidation, 50000ms UI deadline, native final deadline, stale-request rejection and session destruction behavior remain in the original consent implementation. The four resource/manifest files are byte-identical to its legacy result. No new API or broader consent grant is introduced.

The existing ordinary product build invokes this same apply.sh twice in the established prefix/forward flow. The shared systemui_provider.source_ready still loads source_states.json with the unchanged guarded-product-source-vector579/v1 schema and verifies all12 repaired final hashes. No shared helper or build-script edit is required. Real compilation and new-QEMU allow/deny/stale/restart/cleanup validation remain required.
