# Public contact selection result protocol

Apply after `contacts_data/sync_mode` on fixed project
`c73bd27daa3fcd8ed6099b17cbffbd7021e3873e`. The exact guard accepts only all
five predecessor files or all five final files. Root must extend the preceding
`sync_mode` guard to recognize this complete successor before whole-stack replay.

The four `selectContacts` overloads and two deprecated `selectContact` overloads
retain the actual Contacts provider, permissions and DTOs. Failures produce
BusinessError objects, malformed/partial data cannot become successful arrays,
and the API26 navigation-dismiss option reaches the actual modal config. A
per-request, bounded 10-minute libuv timer and async notification avoid blocking
NAPI worker threads. UI callbacks retain no `napi_value` or raw BaseContext;
completion runs under a handle scope on the owning JS loop. Cleanup, release,
startup failure and destruction settle or cancel each request once. Window close
reacquires the same live host UIContent and closes only that request's session.

The pure protocol validates Want parameter types, bounds before indexing or
arithmetic, unique indices, complete 100-contact frames, stable total, JSON
object arrays and exact aggregate count. It bounds JSON depth to 64, one frame
to 16 MiB and aggregate input/output to 128 MiB. Valid code-0 default selection
is preserved when the user cancels; code-1 cancellation returns an empty array.
Frames after a terminal result are ignored. The existing permissions are intact.

This component changes the public **selection** path. Legacy save/import helpers
retain their separate transport; their raw callback/busy-wait/splice code has not
been certified by this selection repair. Real product TU/ABC builds and fresh
package UI, permission and lifecycle checks remain root integration gates.

Host evidence: 86 actual JS wrapper scenarios, 44 actual header protocol
challenges and 17 extracted native lifecycle adapter scenarios. Darwin ASan and
UBSan pass; the first unsupported `detect_leaks=1` failure is preserved. Darwin
has no LeakSanitizer support. These are host adapters, not system runtime proof.
